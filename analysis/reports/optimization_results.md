# Conversational Search Agent：评测器驱动的检索优化与扩展集验证

本文记录当前 Agent 的优化闭环。目标不是背下公开 200 条样本，而是先复现评测器实际暴露的信息，再用公开集相对 5 万商品目录的分布偏移作为弱先验，并在一个包含原始样本的 2000 条近邻扩展集上检验泛化。

## 1. 从评测器行为反推可用信号

评测器每轮先调用 `Agent.respond()`，再依据返回的 `ask_attribute` 生成模拟用户回复。选择 `other` 时，它会从目标商品尚未披露的约束里继续给出最多两个属性，因此当前实现每轮都询问 `other`，同时始终返回合法候选，而不是只提问不推荐。

属性卡片并不是完整商品描述。它按固定顺序构建：材质正则命中项、颜色正则命中项、`features`、`details`，最后才可能加入预算。Agent 在本地复刻同一构建顺序，并为每个商品建立：

- 精确约束倒排索引；
- 属性卡片前缀索引；
- 标题、类目与属性的 SQLite FTS5 检索索引。

这样一来，回复中出现的约束用于交集筛选；更重要的是，已经披露出的属性序列也用于前缀筛选。由于材质和颜色只有正则命中时才会进入属性卡片，前缀位置本身也包含“前面没有该类属性”的负证据。这正是对“商品中没有相应词时可直接筛选”这一提示的落实。

## 2. 公开 200 条与全量目录的分布偏移

脚本 `analysis/build_expanded_eval_set.py` 对 5 万商品和 200 个公开目标使用同一套特征提取函数，生成完整报告 `analysis/reports/public_catalog_distribution.md` 和机器可读文件 `analysis/reports/public_catalog_distribution.json`。

若记某个离散属性值为 \(v\)，平滑后的优先级采用对数 lift：

```text
lift(v) = (P_public(v) + eps) / (P_catalog(v) + eps)
prior(v) = log(lift(v))
```

只保留在公开目标中至少出现 3 次的值，避免单个偶然样本制造极端权重。最明显的偏移包括：

| 属性 | 目录占比 | 公开目标占比 | lift |
|---|---:|---:|---:|
| 评论数 `1000_plus` | 3.066% | 74.500% | 24.299 |
| 价格 `10_to_25` | 9.206% | 44.000% | 4.779 |
| 价格 `25_to_50` | 5.334% | 32.500% | 6.093 |
| 评分 `4.0_to_4.49` | 34.208% | 48.500% | 1.418 |
| 缺失或无效价格 | 79.180% | 11.000% | 0.139 |
| 评论数 `under_10` | 45.014% | 1.000% | 0.022 |
| 评分低于 3.5 | 14.878% | 0.000% | 接近 0 |

这些值只作为候选排序的弱先验，不能覆盖用户已经明确给出的约束。当前排序中，精确约束匹配和属性卡片前缀匹配的权重远高于分布先验。

## 3. 构造 2000 条公开分布近邻集

扩展集保留原始 200 条，并为每个公开目标从目录中选择 9 个不重复近邻，总计 2000 个唯一目标。近邻相似度综合类目、材质、颜色、评分桶、评论数桶、价格桶、卡片属性类型、约束 Jaccard 相似度和公开集先验。

原始样本的场景和难度分布被精确放大 10 倍：

| 维度 | 数量 |
|---|---:|
| 原始公开目标 | 200 |
| 合成近邻目标 | 1800 |
| 总目标数 | 2000 |
| buying | 800 |
| browsing | 800 |
| intent_override | 300 |
| boundary | 100 |

需要明确：这是一套依据公开抽样偏移构造的压力测试集，不是隐藏 800 条的真实标签，也不能证明与官方隐藏集同分布。它的价值是防止只在公开 200 条上调参，并比较先验是否在相似但未见过的商品上仍然有效。

## 4. 三组对照实验

三个版本使用同一套检索、询问和筛选逻辑，只改变分布先验权重：

| 版本 | HR@10 | MRR | MTTC | Efficiency | Technical Score |
|---|---:|---:|---:|---:|---:|
| 扩展集，无先验 | 0.9950 | 0.952157 | 3.0665 | 0.79335 | 0.941817 |
| 扩展集，先验权重 8 | 0.9980 | 0.948599 | 3.0255 | 0.79745 | 0.943070 |
| 扩展集，先验权重 4 | **0.9985** | **0.956493** | **2.9515** | **0.80485** | **0.947168** |

权重 8 虽然减少漏检，却损伤了总体排序；权重 4 在命中率、MRR、轮数和综合分之间取得了更好的折中，因此作为当前默认值。

当前版本在公开 200 条上的结果为：

| HR@10 | MRR | MTTC | Efficiency | Technical Score |
|---:|---:|---:|---:|---:|
| **1.0000** | **0.984167** | **2.6450** | **0.83550** | **0.962350** |

扩展集按场景拆分后的权重 4 结果如下：

| 场景 | HR@10 | MRR | MTTC |
|---|---:|---:|---:|
| boundary | 1.000000 | 0.955278 | 3.7600 |
| browsing | 0.998750 | 0.954551 | 2.8525 |
| buying | 0.998750 | 0.966770 | 2.5400 |
| intent_override | 0.996667 | 0.934671 | 4.0433 |

`intent_override` 仍是最明显的薄弱项。当前实现会在意图切换时清除旧查询和拒绝集合，同时保留仍然适用的已披露约束；后续优化应优先在这一场景做消融，而不是继续放大公开集先验。

## 5. 复现实验

重新生成分布报告、先验和 2000 条扩展集：

```powershell
python analysis/build_expanded_eval_set.py
```

运行公开集：

```powershell
python -m evaluator.local_evaluator `
  --catalog data/catalog.jsonl `
  --dataset data/public_set.jsonl `
  --output analysis/results/results_keyword_agent.json
```

运行扩展集：

```powershell
python -m evaluator.local_evaluator `
  --catalog data/catalog.jsonl `
  --dataset analysis/generated/expanded_public_like_2000.jsonl `
  --output analysis/results/results_expanded_2000_prior4.json
```

最后运行回归测试：

```powershell
python -m unittest discover -s tests -v
```

## 6. 结论与边界

本轮最高价值的优化并不是简单给“高评分”加权，而是先利用评测器的结构化回复建立精确约束交集，再从属性卡片的构建顺序中恢复负证据，最后才以公开集相对目录的分布偏移打破剩余候选的并列。这个顺序让统计先验只能影响真正模糊的候选，不会推翻已经得到的用户约束。

公开集分数和合成扩展集分数都只是本地证据。隐藏 800 条如果采用相同抽样逻辑，弱先验有机会继续受益；若隐藏集特意修正公开偏移，权重 4 的保守设置也比更强的权重 8 风险更低。
